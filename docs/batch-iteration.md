# 迭代方式与批量结果施工文档

> 状态：已与用户确认，施工完成
>
> 日期：2026-11-09
> 范围：`pixelconfusion` 桌面端 UI、批量处理状态与参数校验；核心置换算法不变。

## 1. 背景

当前程序只有单次处理：

- `PageView` = 顶栏 + 内容列。
- `WorkspaceView` 左栏 = 来源卡（206px）、算法与参数卡（360px）、底部双按钮；右栏 = `StageView`，内部是“输入 / 结果”两个 `PreviewTile`。
- `App._transform()` 校验一次参数，后台调用 `Transformer.apply()`，完成后只保留一个 `result_image`。
- 没有批量任务、结果集、滚动网格、开关控件；`Segmented` 只支持写死的 Gilbert/Arnold 两项。

本次新增“迭代方式”工作区，并在“多次迭代”下支持一次生成多张迭代结果、正反两个方向同时生成、下一批继续搜索，以及结果大图预览与导出。

## 2. 已确认的产品规则

### 2.1 来源图片

- 从左侧栏移到 Header 下方，独占一行，成为横向长条。
- 放在内容列内，与下方左右两栏同宽（不是贴满窗口边缘）。
- 高度约 92–100px。
- 已载入：缩略图 + 文件名 + 尺寸/格式 + 更换/清空按钮；右侧保留“内置测试图/换成内置测试图”入口。
- 空状态：标题与状态 + 横向虚线选择区 + 内置测试图入口。

### 2.2 迭代方式

- 位置：左栏“算法与参数”上方。
- 标题：`迭代方式`。
- 两个分段选项：`单次` / `多次`。
- 单次：保持现有单张处理方式。
- 多次：
  - 新增 `等差迭代次数` 数字输入（默认 10，范围 1–50，下限 1）。
  - 新增开关 `正反自动混淆`（默认关闭）。
  - 多次迭代时隐藏“算法与参数”里的 `迭代次数` 输入框，避免两个次数输入冲突。
  - 算法与参数里的偏移量、a、b 仍有效。

### 2.3 迭代范围与批次

- 本批迭代值为 **1…N**，不展示 0；内部从 0 起步递增，但结果从 1 开始。
- 每批固定 N 张/方向。
- 下一批为 **N+1…2N**；再下一批为 **2N+1…3N**，依此类推。
- 每批结果**替换**上一批，不追加。
- 批次信息需要展示：批次序号、迭代范围（例如 `第 2 批 · 11–20 次`）。

### 2.4 多次迭代 + 未开启正反自动混淆

- 底部仍显示 `反向混淆`（蓝）与 `正向混淆`（玫红）。
- 点任一方向按钮：按当前方向生成整批 N 张，结果替换旧结果。
- 左侧保留输入预览，右侧变成该方向的结果网格。
- 正向/反向按钮每次点击都视为新一批，从 1 开始；切换方向也重新从 1 开始。
- “迭代方式”卡内新增 `下一批` 按钮：
  - 与底部 `反向混淆` / `正向混淆` 使用同规格的整行按钮，独占一行。
  - 第一批完成后可用。
  - 继续**上次使用的方向**，生成 N+1…2N。
  - 按钮下方以小字显示下一批的迭代范围。
  - 自动混淆开启时隐藏此按钮，改用底部“自动下一批混淆”。
- 未选择方向前，右侧标题为 `结果集`，方向圆点为中性色；点击 `反向混淆` 或 `正向混淆` 生成后，标题才变为 `反向结果集` / `正向结果集` 并显示对应方向颜色。
- 批处理模式下，舞台底部原有的 `用作输入` / `保存 PNG` 隐藏；操作改到结果预览窗中完成。

### 2.5 多次迭代 + 开启正反自动混淆

- 底部两个旧按钮消失，替换为两个蓝色主按钮：
  - `自动混淆`
  - `自动下一批混淆`
- 右侧两个大框替换为两个多结果容器：
  - 左框：反向结果集（reverse / restore）。
  - 右框：正向结果集（forward / scramble）。
  - 原图只保留在顶部来源条缩略图。
- `自动混淆`：
  - 从 1…N 生成，正反各 N 张，共 2N 张。
  - 替换旧结果；批次重置为第 1 批。
- `自动下一批混淆`：
  - 第一批完成后可用。
  - 从上一批结束值 +1 开始，生成 N 张/方向。
  - 例如 N=10：第 1 批 1–10，第 2 批 11–20。
  - 替换上一批结果。

### 2.6 结果查看、用作输入与保存

- 点击任意结果缩略图，打开大图预览窗。
- 预览窗展示：方向、第 k 次、批次范围、图片尺寸。
- 预览窗内有两个操作：
  - `用作输入`
  - `保存 PNG`
- `用作输入`：把该结果原尺寸图设为新的来源图片，关闭预览，清空批量结果并重置批次。
- `保存 PNG`：保存该结果原尺寸图，建议文件名包含方向与迭代值，例如 `源文件名_reverse_12.png`。保存不关闭预览。
- 单次模式仍保留舞台底部的 `用作输入` / `保存 PNG`。
- 批处理模式隐藏舞台底部这两个按钮。
- 输入框与结果集始终等宽等高、上下对齐；结果集的滚动条叠加在框内右缘，不改变外框尺寸。

### 2.7 内存与预览策略

- 单批最多 50 张/方向，自动模式最多 100 张结果。
- 若 100 张 1400×1400 RGBA 原图全部驻留内存，约 780MB，不可接受。
- 因此：
  - 结果网格只保留缩略图（建议 128–160px 级别）。
  - 点击缩略图时，按该迭代值重新生成原尺寸图，再打开大图预览。
  - 预览窗打开期间保留该张原图；关闭后释放。
  - 预览生成期间显示加载状态；完成后启用“用作输入/保存 PNG”。
- 由于算法确定性，按迭代值重算的结果与批量时生成的同值结果一致。
- 点击预览时可能等待约 0.5–2 秒（取决于图片尺寸和迭代值），这是控制内存的取舍。

### 2.8 状态重置

以下操作清空批量结果并把批次重置到第 1 批：

- 更换/清空来源图片
- 切换算法
- 修改偏移量、a、b
- 修改等差迭代次数 N
- 切换单次混淆/多次迭代
- 开关正反自动混淆

处理中（`_busy=True`）禁用来源、参数、迭代方式与操作按钮。批量处理期间不提供取消功能（沿用当前单次任务的单飞模型）。

### 2.9 边界

- N 范围 1–50，默认 10。
- 迭代值 k 仍需在 1–1,000,000 之间；若下一批越界，禁用“下一批”。
- Arnold 非正方形仍按现有规则报错。
- 批量生成失败时：停止该批、保留已生成缩略图或清空，显示错误；下次操作重新开始。
- 修改 N、参数或来源后，“下一批”状态失效。

## 3. 目标布局

```
┌──────────────────────────────────────────────────────────────┐
│ Header（品牌 / 步骤 / 帮助）                                  │
├──────────────────────────────────────────────────────────────┤
│ 来源图片（横向长条，内容列内独占一行）                        │
├───────────────────┬──────────────────────────────────────────┤
│ 迭代方式           │ 预览                                      │
│                   │ ┌───────────────┬──────────────────────┐ │
│ 算法与参数         │ │ 输入 / 反向集  │ 结果 / 正向集         │ │
│                   │ │               │                      │ │
│ [反向] [正向]      │ └───────────────┴──────────────────────┘ │
│                   │ 状态 / 进度 / 单次操作按钮                │
└───────────────────┴──────────────────────────────────────────┘
```

舞台三种状态：

1. **single**：左输入 `PreviewTile`，右结果 `PreviewTile`，底部显示“用作输入/保存 PNG”。
2. **batch-single**：左输入 `PreviewTile`，右单个结果网格；底部两个操作按钮隐藏。
3. **batch-auto**：左反向结果网格，右正向结果网格；输入预览隐藏；底部两个操作按钮隐藏。

## 4. 状态模型

`App` 新增/调整：

```python
iteration_mode: str          # "single" | "batch"
auto_mixed: bool             # 正反自动混淆
batch_count: int             # N
batch_start: int             # 当前批起始迭代值
batch_index: int             # 从 1 开始
batch_direction: str | None  # batch-single 下上一批方向："reverse" | "forward"
batch_results: {
    "reverse": list[BatchItem],
    "forward": list[BatchItem],
}
batch_running: bool
last_batch_elapsed: float
```

```python
@dataclass(frozen=True)
class BatchItem:
    direction: str           # "reverse" | "forward"
    iteration: int
    thumbnail: Image.Image   # 仅缩略图，不含原图
```

`App._busy` 继续表示“有后台任务”；批量任务也使用它。`BackgroundRunner` 仍是单飞。

批量任务事件建议：

- `progress`: `(fraction, text)`
- `batch_item`: `(direction, iteration, thumbnail)`
- `done`: `("batch", batch_meta, elapsed)` 或 `("preview", image, meta)`
- `error`: `str`

批量 worker 在后台生成原图，立即缩放成缩略图后丢弃原图；通过 `emit("batch_item", ...)` 把缩略图交给主线程。主线程只负责 `ImageTk.PhotoImage` 和网格更新。

## 5. 参数校验

在 `pixelconfusion/parameters.py` 新增：

- `DEFAULT_BATCH_COUNT = 10`
- `MAX_BATCH_COUNT = 50`
- `BatchRequest` dataclass：
  - method
  - actions（tuple，例如 `("restore",)` 或 `("restore", "scramble")`）
  - start
  - count
  - offset
  - a
  - b
- `build_batch_request(method, actions, start, count_text, offset_text, a_text, b_text, width, height)`
  - 校验 N 为 1–50。
  - 校验 start >= 1 且 start + count - 1 <= MAX_ITERATIONS。
  - 复用现有 method/offset/a/b 校验与 Arnold 正方形校验。
- 单元测试覆盖范围、非正方形、非法 N、越界 start。

`MAX_ITERATIONS` 继续为 1,000,000。
